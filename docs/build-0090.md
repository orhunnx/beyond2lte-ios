# 0090: boot-selected SipHash PACGA experiment

## Change

The embedded loader explicitly adds `b2l_pacga_siphash=1` alongside the existing
`b2l_arm64e_compat=1` development ABI. At TUNABLES the kernel selects exactly one
algorithm for the whole boot. Missing, zero or invalid SipHash opt-in retains
QARMA5; disabling the development runtime also disables the SipHash path.
There is no runtime switch. This is an experimental alternate PACGA result ABI,
not QARMA-compatible output or a new hardware authentication claim.

The callback uses the existing pinned XNU BSD SipHash-2-4 implementation with
`LE64(a) || LE64(b)` and retains only the upper32 result bits. The existing
128-bit boot-shared key is still generated by read_frandom on the first EL0
trap after BSD startup. A release store publishes the completed immutable key;
acquire readers use it without taking the global mutex. Key creation is still
serialized. Keys are never logged or persisted, and all tasks/CPUs share the
same algorithm and key until reboot. A small BSD-side bridge keeps the SipHash context out of Mach VM types.
The bridge and BSD SipHash objects are explicitly compiled with `-mgeneral-regs-only` for the exception path.

The corrected QARMA assembly is included: Darwin now emits the missing ADD
when locating its constants. See [the investigation](pacga-alternatives.md).
Periodic `B2L LIVE` summaries append `pacga=siphash24` or `pacga=qarma5`, allowing
post-boot confirmation without recording keys or operands. PACGA remains excluded from persistent instruction conversion. This change
does not alter the native-cache disk format or erase learned records. The 0089 HID
collection framing repair and previous storage/RAM/scheduler work are retained.

## Verification

Actual production callback and decoder tests run with the pinned XNU SipHash
source adapted only at the host header/platform boundary. Both algorithms pass
ASan/UBSan and ThreadSanitizer runs: eight threads race the first callback,
entropy is invoked once, results match across threads/changing inputs, and a
warm loop takes no mutex. Standard SipHash16-byte known answer, zero low32
bits, boot gates, decoder/register/PC boundaries and unchanged failure state
are covered. Native Mach-O and Cortex-A53 ELF QARMA checks pass1259 independent
frozen vectors; grading and actual mixed-pager regression gates pass.

These tests establish local consistency, not successful startup or faster UI.
The earlier roughly10x arithmetic benchmark was on a Mac and excluded exception
entry, VM checks and scheduling. PACGA still traps, so a whole-system speedup
must be measured on this phone. Persisted userspace assumptions remain part of
the device trial. Kernel build, scalar/RCpc audit and BOOT installation status
are recorded below after completion.
